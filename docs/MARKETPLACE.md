# مركز الأدوات (Marketplace) — المرحلة 8

## الخلاصة
المتجر **مستودع GitHub عام** فيه فهرس ثابت `index.json` موقَّع وحزم `.tarpkg` معتمدة. لا خادم ولا تكلفة ولا حسابات جديدة.
التطبيق يقرأ الملفات من `raw.githubusercontent.com` فقط ويتحقق في Rust قبل أي تثبيت.

## ما الذي يعمل فعلاً
- ضبط المصدر (مشرف التطبيق فقط): المستودع `owner/name` + **المفتاح العام للمراجِع**. لا مستودع افتراضي ولا خدمة مزيّفة.
- **توقيع الفهرس**: `index.sig` توقيع Ed25519 على `"TARPKG-INDEX-V1\n" + بايتات index.json`. فهرس غير موقَّع أو معدَّل أو بمفتاح آخر يُرفض.
- **حماية من التراجع**: حقل `seq` متزايد. يُرفض أي فهرس رقمه أقل من آخر فهرس رُئي (يمنع إعادة فهرس قديم يُخفي الإلغاءات). تغيير المصدر يصفّر العدّاد.
- **التثبيت لا يتم إلا إذا**: الحالة `approved` + حجم وsha256 مطابقان للفهرس + manifest مطابق (id/version) + الصلاحيات المعلنة مطابقة للفهرس + الحزمة موقَّعة **بمفتاح المراجِع نفسه** (أي مرّت بخطوة «توقيع الحزمة المقبولة»). ثم تمر على الفحوص المعتادة لمحرك الأدوات (التحليل الساكن، الصلاحيات المعلنة، رفض الرجوع لإصدار أقدم).
- **مسار الحزمة** يُبنى من `packages/<id>-<version>.tarpkg` بعد التحقق من id وversion، لا من رابط يرسله الفهرس.
- **الإيقاف والإلغاء بعد النشر**: عند فتح المتجر أو تحديثه أو أي تثبيت منه، أي أداة مثبّتة بإصدار `suspended` أو `revoked` تُعطَّل تلقائياً ويُسجَّل ذلك في سجل التدقيق. تفعيلها بعد ذلك للمشرف فقط.
- **الفرق بين الرسمي والمحلي**: بطاقة الأداة تعرض «من المتجر • معتمدة» أو «محلية (للتجربة)». الرسمي = بصمة الحزمة المثبّتة تطابق ما ثُبّت من المتجر.
- **عدم منح صلاحيات**: التثبيت من المتجر لا يمنح أي صلاحية. الموافقة لكل صلاحية على حدة وللمشرف.
- **الإبلاغ والتقييم**: زرّان يبنيان رابط GitHub Issue جاهزاً (وسم `report` / `rating`) تفتحه في المتصفح. التطبيق لا يرسل شيئاً بنفسه.
- الحالات السبع (مسودة، قيد الفحص، قيد المراجعة، مرفوضة، معتمدة، موقوفة، ملغاة) مدعومة في صيغة الفهرس ويعرضها التطبيق. غير المعتمدة لا تُثبَّت.

## إنشاء المتجر (مرة واحدة، على حاسوبك)
```
pip install cryptography
python tools/sign_tarpkg.py keygen --out reviewer.key          # مفتاح المراجِع: الملف سرّي ولا يُرفع لـ GitHub
python tools/market_tool.py init --repo-dir ../my-market --key reviewer.key --name "متجري"
```
يطبع المفتاح العام. ثم أنشئ مستودعاً عاماً على GitHub، وارفع محتويات `my-market` إليه على الفرع `main`.
(الفرع يجب أن يكون `main`.) في التطبيق: الأدوات ← المتجر ← «ضبط المصدر» وأدخل `owner/name` والمفتاح العام.

## دورة المراجعة (أي خطوات آلية وأيّها يدوي)
| الخطوة (من المواصفة) | الواقع |
|---|---|
| 1 استلام الحزمة | Pull Request إلى `submissions/` (يدوي، GitHub) |
| 2 هوية المطوّر والتوقيع | **يدوي** — تقرّره أنت (حساب GitHub، تواصل، سمعة). التطبيق لا يتحقق من هوية المطوّر |
| 3 فحص الملفات والاعتماديات | جزئي: محرك الأدوات يرفض المسارات الخطرة والروابط الرمزية وضخامة الحزمة؛ الاعتماديات تُراجَع يدوياً |
| 4 تحليل الكود | آلي جزئي: Security Lab في التطبيق (استخراج الصلاحيات من الأوامر) — ليس تحليلاً كاملاً |
| 5 اختبار في بيئة معزولة | **يدوي** على جهاز/VM مخصص؛ التطبيق لا يملك عزلاً ديناميكياً (انظر docs/ISOLATION.md) |
| 6 مراقبة السلوك | **يدوي** |
| 7 مراجعة الصلاحيات | يدوي بمساعدة تقرير Security Lab |
| 8 القرار | يدوي |
| 9 توقيع الحزمة المقبولة | آلي: `market_tool.py add` |
| 10 نشر الإصدار | `git push` للمستودع |

## إيقاف إصدار ضار بعد النشر
```
python tools/market_tool.py set-status demo 1.0.0 revoked --repo-dir ../my-market --key reviewer.key --notes "السبب"
```
ثم ارفع التغيير. يصل المستخدمين عند فتحهم المتجر لاحقاً (GitHub يخزّن الملفات الخام مؤقتاً بضع دقائق).

## حدود صريحة
- المراجعة ليست ضماناً مطلقاً للأمان، وقبول الأداة لا يثبت أنها آمنة 100%.
- الإيقاف **لا يعمل إلا عند اتصال المستخدم بالمتجر**. جهاز غير متصل أو لا يفتح المتجر يظل يشغّل الإصدار الملغى.
- من يملك **مفتاح المراجِع الخاص** يستطيع توقيع أي شيء. احفظه خارج GitHub ونسخة احتياطية آمنة. لا توجد آلية تدوير مفاتيح آلية: عند تسريبه أنشئ مفتاحاً جديداً وأعطِ المستخدمين المفتاح الجديد (تغيير المصدر).
- المفتاح العام يجب أن يصل المستخدم عبر قناة غير المستودع، وإلا لا قيمة للتحقق.
- لا يوجد نظام حسابات للمطورين ولا رفع مباشر من التطبيق ولا تقييمات آلية: الحقل `rating` في الفهرس يحدّثه المراجِع يدوياً (`market_tool.py rating`).
- حسابات المطوّرين المخصصة (بدل GitHub) غير منفَّذة؛ تُضاف فقط عند الحاجة وبعد قرارك (تحتاج خادماً).
- لم تُجرَّب الشبكة الفعلية بعد: الاختبارات الآلية تستخدم جالباً وهمياً، وتختبر توافق Python↔Rust بملفات مولَّدة. أول تجربة حقيقية تكون على جهازك.

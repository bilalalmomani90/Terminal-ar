# Android — المرحلة 10

## الحالة بصدق
الكود والـ workflow كُتبا ولم **يُترجما ولم يُجرَّبا** على Android (لا Android SDK ولا شبكة crates في بيئة التطوير). أول ترجمة حقيقية في GitHub Actions (`android.yml`)، وأول تشغيل على هاتفك. توقّع أن تظهر أخطاء بناء في الجولة الأولى (أكثرها احتمالاً: توافق `portable-pty` مع Android، وبعض إعدادات Gradle/NDK).

## ما الذي يعمل على Android (تصميماً)
- **طرفية محلية** ضمن صندوق التطبيق: صدفة Android (`/system/bin/sh`) عبر PTY. الأوامر المتاحة هي أوامر Android الأساسية (toybox) فقط، ضمن صلاحيات تطبيقك. لا PowerShell ولا CMD ولا أدوات سطح المكتب. مجلد البدء = مجلد بيانات التطبيق لأن Android بلا `HOME`.
- **أدوات مناسبة للهاتف**: أداة مدمجة واحدة `unixsys` (uname/hostname/uptime/df/ps) تعمل بأوامر POSIX. أدوات ويندوز المدمجة (net/docker/db/sys) **لا تُسجَّل** على Android (ولا على Linux/macOS). الأدوات الخارجية تعلن `"platforms": ["android"]` لتُثبَّت هنا.
- **الواجهة**: القائمة الجانبية تبدأ مطويّة وتُفتح فوق الشاشة، أزرار أكبر، وشريط مفاتيح تحت الطرفية (Esc, Tab, Ctrl الملتصق, الأسهم, `| / - ~`, Ctrl+C) لأن لوحة اللمس لا تحوي هذه المفاتيح.
- **الاتصال بالكمبيوتر والأجهزة والجلسات**: محرك الاتصال (المرحلة 7) والمتجر (المرحلة 8) مكتوبان بلا اعتماد على نظام معين، لكن **لم يُجرَّبا على Android**. المتوقَّع أن يعمل الهاتف كجهاز *يتحكم* (يقترن بالكمبيوتر ويشغّل أدواته المعتمدة). استضافة الاقتران على الهاتف غير مقصودة.

## ما لا يعمل / غير مضمون
- أي وظيفة تعتمد على أوامر ويندوز أو أدوات غير موجودة في Android.
- Studio: المحرر يعمل نظرياً في WebView، لكن اختبار الأدوات يعتمد على أوامر Android المتاحة. لم يُجرَّب.
- عزل العمليات: لا شيء إضافياً. صندوق Android نفسه يحدّ التطبيق (لا root)، وهذا حدّ من النظام لا ميزة منا.
- تشغيل الخلفية، الإشعارات، مشاركة الملفات: غير منفَّذة.
- AppImage/النوافذ المتعددة/النسخ واللصق المتقدم داخل الطرفية: لم تُفحص على اللمس.

## الإصدار والتوقيع
- **Package ID ثابت**: `com.terminalar.app`. لا يتغير.
- **versionCode** = رقم تشغيل الـ workflow (يزيد مع كل بناء). اسم الملف يحمل الإصدار ورقم البناء.
- **بلا أسرار توقيع (الحالي)**: يُنتَج APK اختبار موقَّع بمفتاح *debug* ويحمل `TEST-debug-key` في اسمه. **ليس مفتاح الإصدار النهائي.** مفتاح debug يتغير بين الأجهزة/البيئات، فقد تحتاج حذف النسخة القديمة قبل تثبيت الجديدة (وهذا ما تفعله الآن أصلاً).
- **مع الأسرار**: أضف في GitHub ← Settings ← Secrets and variables ← Actions أربعة أسرار:
  `ANDROID_KEYSTORE_BASE64` (محتوى ملف keystore بترميز base64)، `ANDROID_KEYSTORE_PASSWORD`، `ANDROID_KEY_ALIAS`، `ANDROID_KEY_PASSWORD`.
  عندها يبني الـ workflow نسخة release ويوقّعها (`zipalign` + `apksigner`) بالمفتاح الثابت ويتحقق من التوقيع. لا يُكتب المفتاح في المستودع.
- إنشاء المفتاح (مرة واحدة، على الكمبيوتر، واحفظه في مكان آمن؛ **فقدانه يعني عدم القدرة على تحديث التطبيق فوق النسخة القديمة**):
  ```
  keytool -genkeypair -v -keystore release.jks -alias terminalar -keyalg RSA -keysize 2048 -validity 10000
  certutil -encode release.jks release.b64      (ويندوز؛ انسخ ما بين سطري BEGIN/END فقط)
  ```

## الإعلانات (Start.io) — القسم 21
**لا إعلانات في هذا البناء إطلاقاً.** اخترتَ البناء بلا إعلانات حتى يتوفر معرّف التطبيق. لم أخترع معرّفاً ولم أضع تجريبياً.

ما نُفِّذ فعلاً هو **طبقة السياسة** (`ads.rs`) مع اختباراتها، جاهزة لوصل Start.io:
| الشرط (من المواصفة) | التنفيذ |
|---|---|
| لا إعلان عند التشغيل | رفض أول 3 دقائق بعد فتح التطبيق |
| لا إعلان عند كل انتقال | لا يوجد مشغّل تلقائي؛ تُستدعى السياسة فقط عند لحظتين: `task_done` و`section_change` (حالياً عند إغلاق المتجر) |
| حد 3 في اليوم + عدّاد | **3 كحد أقصى في أي 24 ساعة متحركة** (أشد من اليوم التقويمي، ولا يعتمد على المنطقة الزمنية). يُحتسب عند منح الإذن فلا يُتجاوز حتى لو تكرر الطلب أو فشل العرض. العدّاد في قاعدة البيانات المحلية |
| فاصل مناسب | 15 دقيقة على الأقل بين إعلانين |
| لا أثناء أمر/عملية حساسة | يُرفض إن كان تدفق يعمل أو عملية حساسة |
| لا يقاطع الطرفية | يُرفض إن كانت الطرفية في التركيز |
| لا فوق نوافذ الصلاحيات/التحذيرات | يُرفض إن كانت أي نافذة مفتوحة |
| تحكم مركزي | مفتاح `ads.enabled` للمشرف فقط (صفحة المشرف ← تفعيل/تعطيل الإعلانات). الافتراضي معطّل |
| فشل التحميل لا يعطّل شيئاً | القرار مستقل تماماً؛ أي خطأ يُبلَع بصمت |
| ليست شرطاً لوظيفة | لا وظيفة تنتظر الإعلان |
| لا إعلان يشغّل أوامر | غير ممكن: الإعلان لا يملك أي واجهة إلى محرك الأوامر |
| لا إعلانات على Windows | الكود يعيد «غير متاح» على أي نظام غير Android |

**ما لم يُنفَّذ**: جسر Start.io نفسه (SDK + معرّف التطبيق + عرض الإعلان). يحتاج منك:
1. حساب في start.io وتسجيل تطبيق Android بالمعرّف `com.terminalar.app`.
2. إرسال **App ID** لي (ليس سرّياً؛ يُدمج في الـ APK). سأخزّنه كمتغيّر (Variable) في GitHub لا كسر.
3. حينها أنفّذ التكامل وفق وثائق Start.io الرسمية وقت ذاك (لا من الذاكرة)، وأقلب `PROVIDER_COMPILED`.

ملاحظة لسياسة المتجر: إن استخدمتَ إعلانات، يجب أن تصرّح بذلك في Google Play (Data safety) وسياسة الخصوصية. لم أتحقق من متطلبات Start.io لسياسة الموافقة (GDPR/UMP) وسأفعل عند التكامل.

## ما يلزم بعد نجاح أول بناء
اختبر على الهاتف: فتح التطبيق، فتح طرفية، `uname -a`, شريط المفاتيح، الأداة `unixsys`، المتجر، ثم أخبرني بالأخطاء لنجمعها.

# دعم Linux وmacOS — المرحلة 9

## الحالة بصدق
الكود كُتب وفُحص تنسيقاً وأنواعاً فقط. **لم يُترجم ولم يُجرَّب على Linux أو macOS بعد.** أول ترجمة واختبار حقيقيان يحدثان في GitHub Actions (`.github/workflows/unix.yml`)، وأول تجربة يدوية عندك. ما يلي هو ما صُمّم، لا ما ثبت.

## Platform Adapters (ما الذي يختلف بين المنصات)
| الجانب | Windows | Linux / macOS |
|---|---|---|
| الطرفية (PTY) | ConPTY عبر portable-pty | PTY يونكس عبر portable-pty |
| الصدفة | PowerShell أو CMD | صدفة المستخدم `$SHELL` (أو `/bin/sh` إن لم تتوفر). على macOS تُفتح كصدفة دخول `-l` |
| الترميز | UTF-8 يُفرض في الصدفة | إن لم يرث التطبيق `LANG` يُضبط `C.UTF-8` (Linux) أو `en_US.UTF-8` (macOS) حتى لا تتعطل العربية |
| تنفيذ التدفقات (Workflow) | `powershell -Command` / `cmd /C` | `sh -c` (و`pwsh` إن طُلبت PowerShell صراحةً وكانت مثبتة؛ وإلا خطأ حقيقي) |
| صدفة الإجراء في manifest | `powershell` / `cmd` / `any` | `sh` / `any`. `powershell` و`cmd` لا تُشغَّل على يونكس ويُرفض الإجراء برسالة واضحة |
| كتالوج الأوامر الجاهزة | الكتالوج الكامل (ويندوز) | كتالوج صغير من أوامر POSIX فعلية (`uname`, `df`, `ps`…). كتالوج ويندوز لا يُعرض لأن أوامره لا تعمل هناك |
| فتح مجلد البيانات (مشرف) | `explorer` | `xdg-open` / `open` |
| البناء | NSIS (.exe) | Linux: `.deb` و`.AppImage`. macOS: `.app` مضغوط |

## الصلاحيات والمحلل الساكن
أُضيفت قواعد تحليل لأوامر يونكس (`rm`, `cp`, `curl | sh`, `sudo`, `systemctl`, `kill`, `crontab`, `apt`…) إلى نفس نموذج الصلاحيات (`files.delete`, `network`, `elevated`…). الأوامر الملتبسة لغوياً (`id`, `ps`, `top`, `find`…) تُطابق فقط في موضع الأمر (بعد `;` `&` `|` `(` أو `sudo`) لتقليل الإنذارات الكاذبة داخل النصوص. **المحلل نصي وليس مفسِّر صدفة**: يمكن التحايل عليه بأساليب الصدفة (متغيرات، `$(...)`، أسماء مستعارة). لا يُعدّ حدّاً أمنياً مطلقاً (كما في ويندوز).

## العزل (دراسة فقط — غير منفَّذ)
التطبيق لا يعزل العمليات على أي منصة؛ الحماية الحالية هي: الإعلان الصادق للصلاحيات + موافقة المشرف + تحليل ساكن + تأكيد التشغيل. خيارات مستقبلية للدراسة:
- **Linux**: `bubblewrap`/namespaces (مستخدم، شبكة، mount) وقيود `seccomp`، أو **Landlock** (نواة 5.13+) لتقييد الوصول إلى الملفات دون صلاحيات root. ميزة Landlock أنها لا تحتاج حاوية؛ عيبها اختلاف الدعم حسب النواة.
- **macOS**: App Sandbox (entitlements) يحدّ التطبيق نفسه لا الأوامر التي يشغّلها بسهولة؛ `sandbox-exec` يعمل لكنه موسوم رسمياً بأنه مهجور. عزل أوامر المستخدم الحرة على macOS صعب بلا اتفاقيات صلاحيات واضحة.
- أي منهما يتطلب تجربة فعلية قبل الادعاء بحماية.

## التوزيع
- Linux: `.deb` و`.AppImage` من الـ Actions. غير موقّعة.
- macOS: `.app` **غير موقّعة وغير موثَّقة (notarized)**. عند أول فتح يمنعها Gatekeeper؛ الفتح: كليك يمين ← فتح، أو من إعدادات الخصوصية والأمان ← «فتح على أي حال». التوقيع والتوثيق الحقيقيان يحتاجان حساب Apple Developer مدفوعاً وأسراراً في GitHub (ولن تُحفظ في المستودع).
- أيقونة macOS (`.icns`) تُولَّد وقت البناء من `icon.png` (256px) فقد تبدو غير حادة؛ استبدل `icon.png` بصورة 1024px لاحقاً.

## ما لم يُتحقق منه / حدود معروفة
- ترجمة Rust على Linux/macOS (تبعيات النظام: `libwebkit2gtk-4.1` وغيرها مذكورة في ملف الـ workflow).
- كل اختبارات Rust القديمة تُشغَّل الآن على يونكس لأول مرة؛ قد يفشل بعضها لافتراضات ويندوز فيها. النتائج في `test-results.txt` ضمن الـ artifact.
- استوديو الأدوات: التوصيات الإرشادية (Guided recipes) كلها PowerShell؛ لا وصفات يونكس بعد. كشف بيئات التشغيل (node/python) لم يُجرَّب على يونكس.
- الاتصال (المرحلة 7) والمتجر (المرحلة 8) نظرياً مستقلان عن المنصة لكن لم يُجرَّبا على يونكس.
- Wayland/X11 والحافظة والخطوط العربية في WebKitGTK لم تُفحص.
- فتح المسارات `~` واختلاف `HOME`: `default_cwd` يستخدم `HOME`.

## الاختبارات المضافة (تعمل على يونكس فقط)
`u01` أمر فعلي ونتيجة صحيحة، `u02` رمز خروج حقيقي (7)، `u03` العربية تمر سليمة، `u04` مجلد العمل يُطبَّق والصدفة الافتراضية تُفتح، `u05` الإيقاف يُنهي العملية، `u06` رفض powershell/cmd على يونكس. ومعها حالات جديدة لقواعد الصلاحيات (أوامر مقبولة وأخرى يجب ألا تُنذِر).

# Workflow Engine (المرحلة 6)

تدفق = ملف JSON محفوظ في قاعدة البيانات (جدول `workflows`)، يُدار من تبويب الأدوات ← «سير العمل».

## الصيغة
```json
{
  "id": "system-check",            // slug: أحرف إنجليزية صغيرة وأرقام و -
  "name": "فحص سريع",
  "description": "",
  "variables": { "label": "x" },   // نصوص تصل للأوامر كـ $env:TAR_VAR_LABEL
  "steps": [
    { "id": "host", "run": "hostname", "shell": "powershell|cmd", "onError": "stop|continue",
      "retries": 0, "timeoutSec": 120,
      "when": { "step": "a", "exitCode": 0 } },
    { "id": "t", "tool": "net", "action": "ip" },
    { "id": "g", "parallel": [ { "id": "p1", "run": "..." }, { "id": "p2", "run": "..." } ] }
  ]
}
```
- **الشروط `when`** (واحد فقط لكل شرط): `{step, exitCode}` أو `{step, stdoutContains}` أو `{step, stdoutEquals}` أو `{step, status: ok|failed|skipped}` أو `{var, equals}`؛ و`not: true` يعكسها. تقرأ نتائج خطوات سابقة فقط.
- **تمرير النتائج**: متغيرات بيئة فقط، لا استبدال داخل نص الأمر (منعاً للحقن): `TAR_STEP_<ID>_STDOUT` و`_EXITCODE` و`_STATUS` و`TAR_VAR_<NAME>` (المعرّف بحروف كبيرة وبـ `-` ⇐ `_`). كل قيمة تُقتطع عند 16000 حرف.
- **معالجة الأخطاء**: `onError: stop` (الافتراضي) يوقف التدفق ويتخطى الباقي؛ `continue` يكمل. `retries` حتى 3 محاولات إضافية. المهلة لكل أمر.
- **التوازي**: مجموعة `parallel` (بلا تداخل)، وأبناؤها لا يرون نتائج بعضهم. مسموح فقط للأوامر التي لا تحتاج غير `system.read` و`files.read` و`network` (+`process.run`)، ويُرفض غير ذلك عند الفحص.
- **حالة التشغيل**: `ok` | `partial` (فشلت خطوة وكانت `continue`) | `failed` | `cancelled`.

## الأمان
- كل أمر يمر بالفحص الساكن نفسه للأدوات (RULE_DEFS). الصلاحيات المطلوبة تُحسب عند كل تشغيل، ولا يعمل التدفق إلا إذا مُنحت كلها للتدفق (مفتاح `wf:<id>` في `tool_grants`) — والموافقة **للمشرف فقط** (مفروضة في Rust).
- خطوات `tool` تمر عبر `security::plan_run` (صلاحيات الأداة المنفصلة وتعطيلها).
- قبل التشغيل تُعرض كل الأوامر ويُطلب تأكيد.
- تُسجَّل في سجل التدقيق: الحفظ والحذف ومنح الصلاحيات وبدء التدفق ونهايته وإيقافه.
- لا عزل ديناميكي: الأوامر تعمل بصلاحيات المستخدم. الفحص الساكن لا يضمن الأمان (docs/ISOLATION.md).

## الإيقاف والسجل
- زر «إيقاف» يقتل العملية الجارية ويتخطى الباقي. آخر 50 تشغيلاً لكل تدفق محفوظة مع مخرجات كل خطوة (مقتطعة 20KB/8KB).
- تشغيل علق عند إغلاق التطبيق يُعلَّم `failed` عند الإقلاع التالي.

## ما لم يُنجز بعد (بصراحة)
- لا محرر مرئي (سحب وإفلات)؛ التحرير بـ JSON مع فحص حي.
- المخرجات تظهر عند انتهاء كل خطوة وليس سطراً بسطر.
- لا تغليف التدفق كحزمة `.tarpkg` مستقلة (engine = workflow) بعد.
- الإيقاف يقتل العملية الأولى؛ عمليات أبناء قد تبقى في حالات نادرة.
